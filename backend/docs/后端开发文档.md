## 1. 项目概述

### 1.1 项目背景

FreshID 是一款智能果蔬识别应用，后端负责提供图像识别、数据存储、用户管理、云端同步等核心服务。

### 1.2 项目目标

- 提供高性能的图像识别 API 接口
- 实现用户数据的安全存储与云端同步
- 支持多用户场景的数据隔离
- 支持游客模式和登录模式两种使用场景
- 保证服务的稳定性和可扩展性

### 1.3 核心功能

#### App 端功能
- 果蔬图像识别
- 用户管理（游客/登录）
- 识别记录管理（CRUD、收藏、清空）
- 云端数据同步（增量同步、冲突处理、删除同步）
- 用户配置管理（语言、自动保存等，支持多设备同步）
- 版本检查更新
- 隐私协议版本管理

## 2. 技术架构

### 2.1 技术栈

| 类别           | 技术选型                   | 说明                  |
| ------------ | ---------------------- | ------------------- |
| **Web 框架**   | FastAPI                | 高性能异步 Python Web 框架 |
| **ASGI 服务器** | Uvicorn                | 生产级 ASGI 服务器        |
| **数据库**      | MySQL                  | 关系型数据库              |
| **ORM/连接**   | mysql-connector-python | MySQL 官方 Python 连接器 |
| **数据验证**     | Pydantic               | 数据验证与序列化            |
| **深度学习**     | PyTorch                | 深度学习框架              |
| **图像处理**     | Pillow                 | Python 图像处理库        |
| **数值计算**     | NumPy                  | 科学计算库               |
| **异步文件操作**   | aiofiles               | 异步文件读写              |
| **文件上传处理**   | python-multipart       | 多部分表单数据解析           |
| **认证**        | python-jose            | JWT 令牌生成与验证          |
| **文件类型校验**   | python-magic           | 文件头（Magic Number）校验    |
| **缓存/限流**     | Redis                  | 可选，用于缓存和限流          |

## 3. API 接口设计

### 3.1 基础信息

- **Base URL**：`http://localhost:8000/api/v1`
- **响应格式**：JSON
- **认证方式**：JWT (Bearer Token)

### 3.2 通用响应格式

```json
{
  "success": true,
  "data": { ... },
  "message": "操作成功"
}
```

### 3.3 通用错误响应

```json
{
  "success": false,
  "code": 1001,
  "error_code": 400,
  "message": "错误描述",
  "details": {}
}
```

## 5. 核心业务逻辑

### 5.1 用户 UID 生成逻辑

**规则：**
- 登录用户（phone）：UID 为 8 位数字，从 00000001 开始顺序递增
- 游客用户：没有 UID
- 最大登录用户 UID 为 99999999
- 使用数据库配置表或原子操作确保唯一性

**实现示例：**

```python
async def generate_login_uid() -> str:
    """生成登录用户 UID（8位数字）"""
    last_uid = await get_global_setting("last_login_uid")
    new_uid = int(last_uid) + 1
    if new_uid > 99999999:
        raise Exception("UID 已达上限")
    await update_global_setting("last_login_uid", str(new_uid))
    return f"{new_uid:08d}"
```

### 5.2 游客模式流程

```
App 首次启动
    ↓
检查是否有本地游客用户
    ↓（无）
调用 POST /users/guest 创建游客用户
    ↓
保存 Token 到本地
    ↓
返回游客模式可用
```

### 5.3 验证码逻辑

**规则：**
- 验证码有效期：5 分钟
- 同一手机号 60 秒内只能发送一次
- 验证码使用后立即失效
- 验证码为 6 位数字

**数据清理：**
- 定期清理过期或已使用的验证码记录
- 建议通过定时任务（如每天凌晨）删除 `expires_at` 早于当前时间的记录

### 5.4 图像识别流程

```
用户上传图像
    ↓
图像校验（尺寸、格式、大小）
    ↓
文件类型校验（MIME + 扩展名 + Magic Number）
    ↓
保存图像到本地
    ↓
图像预处理（resize、归一化）
    ↓
模型推理
    ↓
结果解析（置信度判断）
    ↓
检查用户 auto_save 设置
    ↓（开启）
保存识别记录到数据库
    ↓
更新 sync_status 为 pending
    ↓
返回识别结果
```

#### 5.4.1 图像校验规则

| 校验项  | 规则                   |
| ---- | -------------------- |
| 格式   | 支持 jpg、jpeg、png、webp |
| 最小尺寸 | 480×480px            |
| 最大尺寸 | 2048×2048px          |
| 文件大小 | ≤ 10MB               |

#### 5.4.2 文件类型校验规则

1. **MIME 类型检查**：验证 Content-Type 头
2. **扩展名检查**：验证文件扩展名
3. **Magic Number 检查**：使用 `python-magic` 读取文件头验证真实文件类型
4. **拒绝可执行文件**：防止脚本伪装成图片

#### 5.4.3 置信度处理规则

| 置信度范围     | 处理方式                   |
| --------- | ---------------------- |
| ≥ 80%     | 直接展示结果，关联营养数据          |
| 60% - 80% | 展示"疑似 XX"，推荐 2-3 种相似果蔬 |
| < 60%     | 识别失败，引导重新拍摄            |

### 5.5 数据同步逻辑

#### 5.5.1 数据上传策略

| 网络环境 | 策略     |
| ---- | ------ |
| WiFi | 自动上传   |
| 移动数据 | 弹窗询问用户 |

#### 5.5.2 冲突处理规则

| 数据类型 | 冲突解决策略    |
| ---- | --------- |
| 识别记录 | 以时间最新为准   |
| 收藏状态 | 以最后修改时间为准 |
| 用户信息 | 以云端数据为准   |
| 用户设置 | 以云端数据为准   |

**同步冲突处理示例（伪代码）：**
```python
def resolve_collection_conflict(local_record, cloud_record):
    """解决收藏状态冲突"""
    if local_record.updated_at > cloud_record.updated_at:
        # 本地更新时间更新，使用本地状态
        return local_record.is_collected
    else:
        # 云端更新时间更新，使用云端状态
        return cloud_record.is_collected
```

#### 5.5.3 删除同步策略

- 使用软删除标记 `deleted` 字段
- 上传时携带 `deleted_ids` 列表
- 下载时返回 `deleted_ids` 字段，客户端据此删除本地记录
- 定期清理已标记为删除的记录和对应的图片文件

### 5.6 图片文件生命周期管理

**规则：**
1. **单条删除记录**：同时删除对应图片文件
2. **清空记录**：批量删除关联图片
3. **注销账号**：删除用户所有云端图片
4. **软删除记录**：保留图片文件，直到硬删除时才删除
5. **使用对象存储**：生产环境推荐使用 OSS/S3，便于生命周期管理

### 5.7 识别记录过期清理

- 默认清理周期：3 个月
- 可通过用户设置调整清理周期
- 清理仅删除本地记录，云端记录需单独处理
- 保留收藏的记录不自动清理

### 5.8 用户设置初始化

新用户创建时，自动初始化默认设置：
- auto_save: true
- language: zh-CN
- cloud_sync: false（游客用户）/ true（登录用户）

## 6. 安全与权限

### 6.1 认证机制

**JWT (JSON Web Token)**

- **Access Token**：有效期 2 小时
- **Refresh Token**：有效期 7 天，存储在数据库中
- **Token 存储**：HTTP-only Cookie 或 Authorization Header: Bearer {token}
- **Token 内容**：user_id, login_type, exp
- **Token 撤销**：用户登出或刷新时，使旧 refresh token 失效

**Refresh Token 管理：**
- 存储在 `refresh_tokens` 表中
- 支持手动撤销（`POST /auth/revoke`）
- 定期清理过期和已撤销的 token

### 6.2 数据安全

1. **密码存储**：不使用密码，使用验证码
2. **手机号脱敏**：存储时脱敏，显示为 `138****8000`
3. **敏感数据**：传输过程使用 HTTPS 加密
4. **SQL 注入防护**：使用参数化查询
5. **文件上传安全**：
   - 校验文件类型（MIME 类型 + 扩展名 + Magic Number 检查）
   - 限制文件大小
   - 重命名文件避免路径遍历
   - 存储目录设置合适权限
   - 不执行上传的文件

### 6.3 接口限流

- 识别接口：10 次/分钟/用户
- 验证码发送：1 次/60秒/手机号，5 次/小时/手机号
- 其他接口：60 次/分钟/用户
- **可配置化**：限流值支持通过环境变量配置
